# ADR-045 — Tamagui Adopted in Runtime-Only Mode (No Rspack Compiler Plugin); Build Probe Required Before Screen Work

**Date:** 2026-07-03
**Status:** Accepted — **probe run at the start of Implement; passed, with two concrete fixes applied (see §Probe results)**
**Bolt:** 9 — Navigation, i18n & Design Retrofit

## Context

NFR-10.5 chose Tamagui as the UI/design-system library. Tamagui ships an optional **optimizing compiler** (static style extraction/flattening) with official integrations for Babel, Next.js, and Metro — this project uses **Re.Pack/Rspack**, not Metro, and no verified Rspack-specific Tamagui compiler integration exists as of this writing. Separately, this project's rspack configs already carry a documented gotcha (`rspack.config.mjs`'s `installedVersion()` workaround) for dual ESM/CJS packages whose `package.json` `exports` map confuses Module Federation's version auto-detection when `enablePackageExports: true` is set — Tamagui's package family is exactly this shape (multiple subpackages, modern `exports` maps), so the same class of resolution risk is plausible here, even though (unlike an image-picker or similar) Tamagui's core packages are pure JS/TS with **no native module or podspec surface**, so this is a bundler-integration risk, not a New-Architecture-codegen risk.

## Decision

- Tamagui is used in its documented **runtime-only mode**: `createTamagui()` config + `<TamaguiProvider>` + components imported directly from `tamagui`/`@tamagui/core`, with **no** build-time optimizing compiler plugin wired into `rspack.config.mjs` or either remote config. This is a fully supported Tamagui mode (not a hack) — the trade-off is runtime style-resolution cost only (no compile-time flattening/extraction), not a correctness risk.
- **A build probe is required before any screen is built against Tamagui**, per this project's standing "probe-first" discipline for new dependencies whose bundler/build compatibility on this exact stack (RN 0.86 New Architecture + Re.Pack/Rspack) is unverified: install `tamagui`/`@tamagui/core`/`@tamagui/config`, add a minimal `tamagui.config.ts` + one `<TamaguiProvider>`-wrapped smoke screen, and confirm (a) `yarn tsc --noEmit` is clean, (b) the host bundle actually builds via `re-pack`/Rspack without an `enablePackageExports`-related resolution failure (the same failure mode `installedVersion()` already works around for React Navigation), and (c) the `pools` remote (which will also import Tamagui components per ADR-043) builds cleanly too. If the probe fails, the fallback is documented here rather than discovered mid-Implement: fall back to plain `StyleSheet` + a hand-rolled token module (spacing/color/typography constants) for this bolt's design-system work, and revisit Tamagui in a later bolt once a working bundler integration is found — NFR-10.5 explicitly allows plain `StyleSheet` for simple cases, so this fallback is within the requirement's own stated tolerance, not a scope violation.
- Theming: `TamaguiProvider`'s `defaultTheme` prop is driven by the already-used `useColorScheme()` hook (currently wired only to `StatusBar.barStyle` in `App.tsx`), so light/dark theming exists from the first screen retrofitted, not as a later add-on (per the design-standards instruction to compose themed primitives from the start).

## Probe results (run at the start of Implement, 2026-07-03) — passed, two real fixes required

The probe found two genuine incompatibilities, both fixed, neither requiring the StyleSheet fallback:

1. **`yarn tsc --noEmit` failure on `tamagui@2.4.0`**: `@tamagui/element`'s `package.json` set `"types": "./src"` (pointing TypeScript at raw, un-transpiled source, not compiled `.d.ts`), and its generic `src/index.ts` includes `getWebElement.ts`, which does `element instanceof HTMLElement` — a DOM-lib value reference this project's tsconfig (no `"dom"` in `lib`, RN-only) can't resolve. **Fix: upgraded `tamagui` `2.4.0` → `2.4.2`** — this version's `package.json` `exports` map gained a `"react-native"`-conditioned `types` entry (`./src/index.native.ts`) that this project's `customConditions: ["react-native"]` (already set in `@react-native/typescript-config`) correctly resolves instead, and that native-specific source stubs out `getWebElement` entirely (`export function getWebElement(): never { throw ... }`, no `HTMLElement` reference). Confirmed by inspecting both versions' actual published source (`npm pack`), not just changelog claims. `yarn tsc --noEmit` is clean after the bump.
2. **Rspack bundle failure**: even on `2.4.2`, `tamagui`'s root barrel (`tamagui/dist/esm/index.native.js`) re-exports `@tamagui/popper`/`@tamagui/floating` (Popover/Tooltip/Select/ContextMenu internals) unconditionally, and those packages' own `.native.js` files still `require('react-dom')` at module-eval time — a real packaging gap (dead code on native that the bundler still must resolve statically), not a project misconfiguration. **Fix: `new rspack.IgnorePlugin({ resourceRegExp: /^react-dom$/ })`** added to `rspack.config.mjs`, the same technique already used for `@react-native-masked-view`. Safe because this bolt uses none of Popover/Tooltip/Select/ContextMenu (confirmed by the retrofitted screens' actual component usage — `implement-and-test.md`), so the now-empty `react-dom` module is genuinely unreachable code, not silently broken functionality.

After both fixes: `npx react-native bundle --config rspack.config.mjs --platform ios` (the host) completes successfully (`ios (Rspack 1.7.12) compiled with 6 warnings` — all six are pre-existing-class dynamic-`require` advisories from Supabase/Tamagui/Reanimated, not new errors) producing a real `index.bundle`. `yarn tsc --noEmit` is clean project-wide. A separate, real native-compile probe (`xcodebuild ... -sdk iphonesimulator build`, run for ADR-046's `react-native-reanimated`/`react-native-worklets` addition, see that ADR) also succeeded — `** BUILD SUCCEEDED **`.

One additional advisory (non-blocking, not fixed): Re.Pack logs `"Detected react-native-reanimated package which requires ReanimatedPlugin plugin but it's not configured"` (an optional `@callstack/repack-plugin-reanimated` package, not installed). The build succeeds without it; adding an unverified extra dependency for an advisory-only warning was judged not worth the additional probe surface for this bolt — flagged here for a future bolt if reanimated-driven animations (not just `@react-navigation/drawer`'s own internal usage) are ever added.

## Consequences

- Tamagui proceeds as planned in `design.md §5`, pinned to `2.4.2` (not `2.4.0`) — `package.json`/`yarn.lock` reflect this.
- No StyleSheet fallback was needed — recorded for completeness per this ADR's original contingency plan, not because it was used.

## Post-Implement correction (2026-07-06) — `IgnorePlugin` fix was build-clean but runtime-broken; replaced with a shim alias

The `react-dom` `IgnorePlugin` fix in §Probe results item 2 above was verified only by a successful **static bundle build** (`npx react-native bundle`). That build-time success was misleading: real device/dev-server use crashed at boot with `[runtime not ready]: Error: Cannot find module 'react-dom'`.

**Root cause:** Rspack's `IgnorePlugin` does not replace an ignored request with an empty module — it replaces it with a stub that **throws when actually evaluated** (`__rspack_missing_module`). That's harmless for `@react-native-masked-view` because `@react-navigation/elements` wraps that `require()` in `try/catch` (confirmed by reading `MaskedViewNative.js`). It is fatal for `react-dom`, because `@tamagui/popper/dist/esm/Popper.native.js` has a **static, unconditional top-level** `import { flushSync } from "react-dom"`, unconditionally re-exported through `tamagui`'s root barrel (`create-menu` → `menu` → `tamagui/index.native.js`) — so evaluating it at all (which happens the instant anything imports `tamagui`, i.e. at app boot) executes the throwing stub with no guard.

**Fix:** replaced both `IgnorePlugin({ resourceRegExp: /^react-dom$/ })` entries (host + `pools` remote) with a `resolve.alias` pointing `react-dom` at a real shim module, `src/shared/shims/react-dom-native.ts`, exporting a synchronous pass-through `flushSync`. Verified by fetching the actual dev-server-served bundle (`curl .../index.bundle`) before and after: the pre-fix bundle contained the `Cannot find module 'react-dom'` throw at the exact call sites Tamagui's boot path hits; the post-fix bundle resolves to the shim with zero occurrences remaining. `pools`' own container bundle was independently checked and contains no Tamagui code at all (confirmed only 0 `react-dom`/shim references, 2 unrelated `tamagui` string hits) — expected, since `tamagui` is a **non-eager** MF shared singleton there (§ADR-043): the remote consumes the host's already-evaluated instance rather than bundling its own copy, so it was never at risk from this bug in the first place.

**Lesson for future ADRs in this project:** a successful static `bundle` build is necessary but **not sufficient** to catch this class of bug — `IgnorePlugin` bugs only surface when the ignored module is actually evaluated at runtime, which a build-only probe cannot exercise for code reachable from the app's real boot path. Prefer `resolve.alias` to a real (even no-op) shim over `IgnorePlugin` whenever the ignored import is a static top-level `import` rather than a guarded/optional `require()`.

`rspack.config.mjs` and `rspack.config.pools-remote.mjs` now carry the `react-dom` alias (not `IgnorePlugin`) permanently, pointing at the shim above — re-verify this shim still covers everything actually used if a future bolt adds Popover/Tooltip/Select/ContextMenu-based screens (Tamagui components this bolt doesn't use) that might reach for more of `react-dom`'s API than `flushSync`.

## Post-Implement addition (2026-07-06) — `ReanimatedPlugin` wired in

The "non-blocking advisory" noted above (missing `@callstack/repack-plugin-reanimated`) was resolved: installed `@callstack/repack-plugin-reanimated@5.2.5` (pinned to match the installed `@callstack/repack@5.2.5`) and added `new ReanimatedPlugin()` to `rspack.config.mjs` (host-only, matching ADR-046's host-only reanimated/worklets placement). Per the plugin's own source (`plugin.js`), its module-rule injection is explicitly a documented no-op when using `babel-swc-loader` (this project's loader) — the actual worklets transform already runs correctly via `babel.config.js`'s global `react-native-worklets/plugin`. The plugin is still added because it's Re.Pack's documented integration path and it additionally suppresses reanimated's benign `setUpTests`/critical-dependency build warnings.
