# Tech Stack

> Read by every AI-DLC agent before acting. Keep current.

## Core
- **Framework:** React Native 0.86.0 (New Architecture enabled — `newArchEnabled=true` in `android/gradle.properties`).
- **Bundler:** **Re.Pack** 5.2.5 (`@callstack/repack`) on **Rspack** 1.7.8 — configured in `rspack.config.mjs`. **NOT Metro.** Do not generate Metro-specific config.
  - ⚠️ `metro.config.js` still exists in the repo (RN CLI default scaffold). It is not the active bundler; treat it as legacy and prefer removing it via `/repack-init` cleanup rather than maintaining it.
- **Code splitting / microfrontends:** Module Federation v2 — **not yet configured**. `rspack.config.mjs` currently only wires `Repack.RepackPlugin()` with no host/remote split. Run `/repack-init` to scaffold the actual host + remote topology.
- **JS engine:** Hermes (default for RN 0.86, bytecode chunks, tree-shaking enabled).
- **Language:** TypeScript 5.8 (strict mode via `@react-native/typescript-config`).
- **React:** 19.2.3.

## Conventions
- Lists: **FlashList** (`@shopify/flash-list`) for any scrolling collection — installed since Bolt 5 (ADR-022), MF shared singleton since Bolt 7 (ADR-034).
- Navigation: **React Navigation 7** (`@react-navigation/native` 7.3.4, `@react-navigation/native-stack` 7.17.6 — chosen Bolt 0, ADR-003; MF shared singleton per ADR-002). **2026-07-03 addition, installed and wired (Bolt 9)**: `@react-navigation/bottom-tabs` + `@react-navigation/drawer` added on top of the same library — a nested Drawer→Tabs→per-tab-stack shell (ADR-042): a bottom tab navigator for primary modules (`Home`/`Predictions`/`Pools`, each keeping its own native-stack so a back button is always available), plus a drawer for `Settings`. Not a library swap. Both new packages are host-only MF shared singletons (ADR-043, see Federation boundaries below). `@react-navigation/drawer`'s peer dependency on `react-native-reanimated` (which itself requires the separate `react-native-worklets` package at v4) is also now installed — ADR-046, real native-build-probed (`xcodebuild` succeeded).
- State: **TanStack Query** (server-state/cache) + **Zustand** (client-state) — both chosen Bolt 0, both MF shared singletons since first non-host consumer (Bolt 7, ADR-034; the React Query singleton was load-bearing for correctness, not just bundle size).
- i18n: **i18next + react-i18next + react-native-localize** — chosen 2026-07-03 (requirements.md §10 NFR-10.4), installed and wired (Bolt 9) for device-detected `es`/`en` UI-string translation, defaulting to `es` when the device locale is undetected/unsupported. **Distinct from the existing profile-stored locale preference** (`src/domain/profile/locale.ts`, ADR-012, PROFILE-3 — a business-data field synced to the backend, not app-chrome language) — **ADR-041/044's unify-vs.-independent question is resolved: unification, confirmed by the user.** One explicit choice in `ChangeLocaleScreen`/`LocaleSwitch` now drives the persisted `Profile.locale` field, its local cache, and the rendered `i18next` UI language together (`src/platform/i18n/i18n.ts`, `src/domain/i18n/resolve-initial-language.ts`). String-extraction across Bolts 5-8's screens is **partial, explicitly scoped** — see `bolt-9-navigation-i18n-design-retrofit/implement-and-test.md §6` for exactly which screens got full/partial/no retrofit.
- UI / design system: **Tamagui `2.4.2`** (not `2.4.0` — a real `tsc`/bundler incompatibility in `2.4.0`'s `@tamagui/element` subpackage was found and fixed by this version bump, ADR-045) — chosen 2026-07-03 (requirements.md §10 NFR-10.5), installed and wired (Bolt 9) for shared/reusable component work (`tamagui.config.ts` + `src/shared/design/primitives.tsx`), replacing the current default-RN-starter look on a bounded set of screens. Plain `StyleSheet` **remains acceptable** for simple/one-off cases — not a mandate to rewrite every existing screen in one pass; most Bolt 5-8 screens are still plain `StyleSheet`, explicitly tracked as a follow-up (`implement-and-test.md §6`). Runs in **runtime-only mode** (no Rspack-specific optimizing-compiler plugin exists) — Tamagui's Popper/floating internals leak an unconditional `import { flushSync } from 'react-dom'` even on native; the host + `pools`-remote configs alias `react-dom` to a real shim (`src/shared/shims/react-dom-native.ts`), **not** `IgnorePlugin` (an earlier `IgnorePlugin`-based fix looked correct via a static bundle build but crashed at real boot — ADR-045's "Post-Implement correction" section). Host + `pools` remote MF shared singleton (ADR-043) — theme/context resolves to one instance across those two bundles, same class of risk as the `react-native-svg`/React Query singleton incidents below; proven by actually retrofitting one `pools`-remote screen (`my-pools-screen.tsx`), not just configured. **`tamagui.config.ts`'s `size`/`space` tokens are two genuinely separate scales** (`size` larger, `true: 44`) — a real Layer 2 bug (clipped `PrimaryButton` text) was traced to these having identical, too-small values, since `@tamagui/get-button-sized` derives `Button`'s `height` from `size` and `paddingHorizontal` from `space`.
- Icons: **`lucide-react-native`** (not `@tamagui/lucide-icons`) — added post-Implement (Bolt 9 Layer 2 finding #1) for the bottom tab bar. `@tamagui/lucide-icons` was probed first and rejected: its latest version has no `2.x` line and pulls in a whole nested, disconnected `@tamagui/core@1.x` engine. `lucide-react-native` has zero dependencies of its own and no Tamagui coupling (each icon is a stateless `react-native-svg` render). Host-only MF shared singleton (`rspack.config.mjs`) — see ADR-047 for the full probe record, including a Hermes-parser build issue (`ReanimatedPlugin` + this project's own primary loader both needed adjusting) only caught via a real dev-server build, not a static one.
- Package manager: **Yarn** (resolved Bolt 0 — `package-lock.json` removed, `yarn.lock` is authoritative).

## Federation boundaries
- Host bundle contains: auth, profile (incl. onboarding), predictions (host-placed per requirements.md §7.4), the notification permission/token-registration logic, and — as of 2026-07-03 (Bolt 9) — the top-level bottom-tab + drawer navigation shell arranging Home/Predictions/Pools/Settings (`system-context.md` §7). `scoring` ships as a filesystem-shared library, not a routed chunk (ADR-015).
- Federated remotes: `education` (Bolt 0 demo shell), `pools` (Bolt 7, ADR-032 — the first real feature remote; owns its own internal native-stack navigator, mounted inside the host's `PoolsTab` as of Bolt 9, ADR-042).
- Shared singletons across chunks (`rspack.config.mjs` + every remote config's MF `shared`): `react`, `react-native`, `@react-navigation/native`/`native-stack` (ADR-002/003), `@tanstack/react-query` + the Zustand store module (ADR-034), `@shopify/flash-list` (ADR-034), `react-native-svg` (added Bolt 8, after a real cross-bundle double-registration crash — see `activeContext.md`).
- **Bolt 9 additions (ADR-043), installed and wired — both the host and `pools`-remote bundles were actually built (`npx react-native bundle`) to confirm, not just configured:**
  - Host-only (`rspack.config.mjs` only): `@react-navigation/bottom-tabs`, `@react-navigation/drawer` (ADR-042 — the tab/drawer shell is 100% host code, no remote renders tabs/drawer itself), `react-native-reanimated`/`react-native-worklets` (ADR-046, drawer's peer dependency), `react-native-localize` (only read once at boot by `platform/i18n`, no remote consumes it directly), `lucide-react-native` (ADR-047, tab-bar icons — bundle-size nicety only, no shared-context correctness requirement).
  - Host **and** `pools` remote (`rspack.config.mjs` + `rspack.config.pools-remote.mjs`): `tamagui` (+ one shared theme/context instance — same risk class as the React-Query/`react-native-svg` singleton incidents; proven via `my-pools-screen.tsx`'s real retrofit), `i18next`, `react-i18next`.
  - Both host and `pools`-remote configs alias `react-dom` to `src/shared/shims/react-dom-native.ts` (ADR-045's Post-Implement correction — **not** `IgnorePlugin`, which crashed at real boot despite a clean static build). `rspack.config.mjs` also excludes `lucide-react-native` from its primary loader rule and constructs `ReanimatedPlugin({ unstable_disableTransform: true })` (ADR-047 — a Hermes-parser incompatibility, independent of the `react-dom` issue).
  - `education` remote config is explicitly **unchanged** by Bolt 9 (ADR-043) — not retrofitted with Tamagui/i18n this bolt, still Bolt 0's demo shell; re-audit if a future bolt gives it real screens.
